# JENGA VISION (Dino-Lite) 진행 상황 — 2026-10-19

## 목표
Dino-Lite AM3111로 완성된 젠가 타워의 **블록 짧은 끝면**을 확대해서 보고,
각 블록(N층 M번째)이 **easy(스르륵 빠짐)** 인지 **hard(하중 받는 기둥)** 인지 판별하는 Python 모듈.
로봇 손 젠가 데모에 이식할 예정.

핵심 가설: 하중을 안 받는 블록은 위/아래 층과의 경계에 **틈**이 있고, 이걸 카메라로 볼 수 있다.

## 환경
- uv 프로젝트, Python 3.10, 패키지명 `jenga_vision` (src 레이아웃, 나중에 이식용)
- 의존성: `opencv-python`, `numpy` (scipy 제거함)
- Dino-Lite: `/dev/video0`, **640x480 고정, 30fps**
- **노출/게인 수동 고정 불가** (자동 노출만 됨) → 절대 밝기 말고 주변 대비 비율로 비교해야 함

### 실행 명령
```bash
cd /home/wonik/CES2027/JENGA_VISION_DINO
~/.local/bin/uv run jenga-view      # 라이브 뷰어 (초점/구도 확인)
~/.local/bin/uv run jenga-capture   # 라벨 붙여서 캡처
~/.local/bin/uv run jenga-live      # 실시간 예측 → 밀어보고 정답 입력
```

### 코드 구성
| 파일 | 역할 |
|---|---|
| `src/jenga_vision/camera.py` | `DinoCamera` (OpenCV V4L2), `sharpness()` 초점 점수 |
| `src/jenga_vision/viewer.py` | 라이브 뷰어. `s` 저장, `g` 격자, `q` 종료 |
| `src/jenga_vision/capture.py` | 라벨 캡처. `[ ]` 층, `1 2 3` 위치, `a b` 끝면, `e h u` 라벨, `l` 조명(front/back/both), `SPACE` 저장 |
| `src/jenga_vision/gap.py` | 틈 점수 계산 `analyze(frame) -> GapResult`, 기준선 `EASY_THRESHOLD = 0.4` |
| `src/jenga_vision/live.py` | 실전 테스트. `a`/`b` 누르면 5장 연속 촬영+점수, `e`/`h`로 실제 결과 입력 → `results.csv` |

### 틈 점수 방식 (gap.py)
1. 화면 가운데 1/3 열의 행별 밝기 중간값 → 세로 밝기 프로파일
2. 밝기 변화가 가장 큰 곳을 블록 끝면의 위/아래 경계로 잡음
3. 경계 ±15px 안에서 **좁고 어두운 골짜기**의 깊이를 측정 (0 = 없음, 1 = 새까맘)
4. 프레임 점수 = 위/아래 중 큰 값, 블록 점수 = A면/B면 중 큰 값

### 확인된 것
- 디노 LED만으로 사진 품질, 초점, 구도는 충분함. 틈은 2~5px 두께의 어두운 선으로 찍힘
- 프로그램이 블록 경계 위치는 제대로 찾음 (경계선 그려서 확인)
- **양면을 다 봐야 함**: easy 블록도 대부분 한쪽 끝에서만 틈이 진함 (예: L4P2 A 0.62 / B 0.11)

### 문제
- **hard 블록에도 진한 선이 찍힘.** 지금 점수는 "얼마나 어두운가"만 봐서, 진짜 틈인지 그림자인지 구분을 못함
  - 그림자 후보: 위층 블록의 둥근 모서리, 블록이 살짝 들어가/튀어나와서 생기는 그림자, 블록이 휘어서 끝에만 틈이 있는 경우
- 17개 블록 전체를 점수로 세우면:
  - 0.5 이상: easy 4, hard 1 (0.507, 거의 경계)
  - 0.3 ~ 0.5: easy/hard 섞임 → **구분 불가 구간**
  - 0.3 미만: 전부 hard
- 신호가 약해서 **데이터를 더 모으기보다 측정 방식을 바꾸는 게 먼저**

### 당장 쓸 수 있는 대안 (보류 중)

## 내일 할 일: 백라이트 실험

### 답하려는 질문
> **틈 사이로 새어 나오는 빛으로 easy/hard를 구분할 수 있는가?**

원리: 그림자는 빛을 통과시키지 않지만, 진짜 틈은 반대편에서 빛을 비추면 빛이 샌다.
블록 위나 아래가 길이 방향으로 떠 있으면 B면 쪽에서 비춘 빛이 A면 쪽 경계에서 밝은 선으로 보일 것.

### 준비물
- 핸드폰 손전등 (밝기 최대로 고정)
- 종이 한 장 (핸드폰 앞에 대서 빛 퍼뜨리기)
- 가능하면 방 조명 어둡게

### 1단계: 눈으로 먼저 확인 (5분)
1. `uv run jenga-view` 실행
2. 디노를 **알고 있는 easy 블록**의 A면에 맞춤
3. 반대쪽 B면 뒤에서 핸드폰 불빛을 블록 길이 방향으로 비춤 (5~10cm 거리)
4. 블록 위/아래 경계에 **밝은 선**이 생기는지 확인
5. **hard 블록**으로도 똑같이 해보고 비교
6. 가능하면 디노 LED를 끈 상태와 켠 상태 둘 다 보기

→ 여기서 차이가 눈에 보이면 2단계로. 전혀 안 보이면 그것도 결과임.

### 2단계: 기록 촬영
- 도구: `uv run jenga-capture`
- 블록: 오늘 틀린 4개 **L2P1(easy), L2P2(hard), L4P1(hard), L11P3(hard)** + 맞힌 것 **L2P3(easy), L4P2(hard)**
  - 타워가 오늘 상태 그대로가 아니면: 새로 easy 3개, hard 3개 고르고 **촬영 먼저, 밀어보기는 나중에**
- 블록마다, 각 끝면마다 조명 조건별로 3장씩:
  - `front`: 디노 LED만
  - `back`: 핸드폰만 (디노 LED 끌 수 있을 때만)
  - `both`: 둘 다
- `l` 키로 조건 바꾸고, **찍기 전에 `a`/`b`를 먼저 확인** (오늘 늦게 누른 적 두 번 있었음)
- A면을 찍을 땐 핸드폰은 B면 쪽, B면을 찍을 땐 A면 쪽

### 주의
- 자동 노출이라 핸드폰 빛이 들어오면 화면 전체가 어두워질 수 있음 → 정상
- 같은 층 블록 사이의 **세로 틈**으로도 빛이 샐 수 있음. 우리가 보는 건 **가로선** (위/아래 경계)
- 핸드폰 위치·각도는 최대한 매번 같게 (테이프나 거치대로 고정하면 좋음)

### 성공 기준
easy 블록에서는 적어도 한쪽 끝면의 위/아래 경계에 빛이 새고, hard 블록에서는 안 새면 성공.
그러면 다음 단계로 이 "빛 새는 정도"를 점수로 만들어서 다시 실전 테스트.

## 최종 형태 아이디어: 영상 스캔 (백라이트 실험 이후)

목표: 완벽한 타워를 한 번 쭉 훑어서 → **"N층 M번째, 성공 확률"을 쉬운 순서대로 나열**.

- 영상으로 바꿔도 오늘 정확도 문제(틈 vs 그림자)는 안 풀림 → **신호 먼저 찾고(백라이트), 그 신호를 스캔에 꽂기**
- 경로: 디노 화면 = 끝면 1개 → 한 면에 세로 3줄. 한 면에선 한 층 걸러 끝면이 보임 → 양 끝면 다 보려면 **4면 × 3줄**
- 프레임 → (층, 위치) 매핑: 로봇 팔로 훑으면 카메라 위치로 계산(쉬움). 손으로 훑으면 층 경계선을 세면서 추적해야 함(끝면 나이테 vs 긴 면 결 무늬로 구분 가능, 놓치면 층 번호 밀림)
- 디노는 초점 거리가 짧음 → 거리 일정하게 유지하려면 레일이나 로봇 팔 필요
- 백라이트가 효과 있으면: 카메라 반대편에 빛이 필요 → **탑 전체를 라이트 텐트에 넣는 방식** 검토
- 퍼센트: 지금 17개로는 믿을 만한 숫자 불가. 우선 점수 순서로 나열하고, 데이터 쌓이면 확률로 보정
