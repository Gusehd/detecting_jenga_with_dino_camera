# JENGA VISION (Dino-Lite) 진행 상황 — 2026-10-20

## 목표
- **새로 쌓은(완벽한) 젠가 탑**을 Dino-Lite AM3111로 한 번 스캔해서, 블록마다 "N층 M번째가 얼마나 잘 빠지는지" 순위를 매긴다.
- 로봇 손 젠가 시연(CES2027)에 이식할 Python 모듈이다 (uv 격리 환경, `jenga_vision` 패키지).
- 전제: 완벽한 탑에서 easy 블록은 다른 easy 블록이 빠져도 계속 easy다 → **처음 한 번 스캔한 순위를 끝까지 쓴다.**

### 게임 전략 (2026-10-20 확정)
1. **사이드(바깥) 블록 단계:** 로봇은 사이드 블록만 뽑는다. 순위 1위부터 **7~8개를 한 번도 틀리지 않고** 짚는 것이 목표다. 4개 이상만 보장돼도 사람과 2~3번은 주고받을 수 있다.
2. **가운데 블록 단계:** 사이드가 빠진 층의 가운데는 아무도 안 뺀다(빼면 무너짐). 후보는 세 블록이 다 남은 층뿐이다. 여기부터는 60~70% 확률 승부라 져도 된다.
3. 로봇이 살짝 밀어보고 힘 센서로 판정하는 방식은 **최후의 수단**이다. 카메라만으로 해결하는 것이 목표다.

## 하드웨어 / 촬영 조건
- Dino-Lite Premier (USB a168:09a5), `/dev/video0`, 640x480, 30fps, 자동 노출만 가능.
- **LED 끄기:** 표준 V4L2로는 안 된다. pyusb로 XU 명령을 직접 보낸다 (`jenga-led off`). udev 규칙 `udev/99-dinolite.rules` 설치가 필요하다. 카메라가 스트리밍 중일 때만 명령이 먹는다.
- 촬영: **LED 끔(실내 조명만), 배율 50, 캡을 블록에 밀착, 화면의 하늘색 선과 엣지를 평행하게** 맞춘다.
- **카메라는 고정하고 탑만 90°씩 돌려서** 네 면을 찍는다 → 모든 면이 같은 조명이라 px 값을 그대로 비교할 수 있다.
- 1층은 지그에 가려지고 17층(맨 위)도 안 뽑는다 → **2~16층만** 스캔한다.

### 측정값: 새까만 코어 폭 (`long_edge.measure_single`)
- 엣지 근처 ±40행에서 프레임 중앙값의 25%보다 어두운 행 수를 센다. 16개 세로 줄의 중앙값(px)이다.
- 틈이 진짜 열려 있으면 빛이 안 들어가서 새까맣다. 닫힌 엣지는 회색 그림자만 생긴다.

## 현재 알고리즘 (`jenga-tower` 기본값)

1. **블록 점수:** 사이드 블록마다 위쪽 엣지를 왼쪽 / 가운데 / 오른쪽 3장 찍고, 그 **중앙값**을 쓴다 (`--agg mean|min`으로 바꿀 수 있음).
2. **층 점수:** 같은 층의 사이드 두 개(P1, P3) 중 **큰 값**을 쓴다.
3. **순서:** 층 점수가 높은 층부터 그 층의 사이드 두 개를 연달아 뽑는다. 층 안에서는 자기 점수가 큰 쪽이 먼저다.
   - 층 점수가 같으면: 짝(작은 쪽) 점수가 큰 층을 먼저, 그것도 같으면 **위층**을 먼저 뽑는다.
4. **SURE 표시:** 층 점수가 16px 이상이면 SURE로 표시한다. 순서에는 영향을 안 주고, 사이드 단계에서 가운데 단계로 넘어갈 시점을 정하는 참고값이다.
5. 가운데 블록은 촬영하지도 추천하지도 않는다 (`--with-middle`, `--middle-below 14`로 예전 방식을 켤 수 있음).

왜 층 순서가 효과가 있나: 틈이 크게 벌어진 층에서는 **사이드 두 개가 같이 easy**였다 (세 번의 스캔 모두). 그래서 한쪽 점수가 애매해도 짝이 확실하면 같이 앞으로 올라온다.
- 예: 둘째 탑 L12는 P1이 26px, P3가 13.5px였는데 둘 다 easy.

## 시도 중인 플랜: 이음매 높이 비교 (`jenga-seam`)

### 아이디어
- 위층은 **같은 층 세 블록 중 제일 높은(두꺼운) 블록**에 얹힌다. 지금까지 잰 틈은 그 결과로 생긴 증상이고, 이 방식은 원인(높이)을 직접 본다.
- 끝면 쪽에서 한 층을 보면 세 블록이 나란히 보이고, **셋 다 같은 위층 블록 하나**를 기준으로 틈이 생긴다.
- Dino를 **이음매**(왼쪽 블록|가운데, 가운데|오른쪽 블록)에 맞추면 한 사진에 두 블록의 틈이 같이 들어온다. **틈이 더 큰 쪽이 더 낮다 = easy 후보.**

```
  ════════════ 위층 블록 ════════════
            ┌──────────┐
  ┌────────┐│          │┌────────┐
  │  왼쪽  ││   가운데  ││  오른쪽 │     ← 가운데가 높으면 양쪽 사이드 easy
  └────────┘└──────────┘└────────┘
          이음매1      이음매2
```

### 기대하는 장점
1. 같은 사진 안에서 비교하니까 조명, 자동 노출, 배율, 카메라 기울기가 상쇄된다.
2. 위층이 기울어서 생기는 "틈은 있는데 hard" 문제를 덜 탈 수 있다.
3. **가운데 블록을 직접 판정**할 수 있다. 사이드로 추론할 필요가 없다.

### 걱정
- 블록 모서리가 둥글어서 이음매 바로 옆은 측정이 안 된다 (이음매 양쪽 50px은 빼고 잰다).
- 예전 가운데 끝면 단독 측정은 실패했다. 차이점은 이번엔 한 사진 안에서 두 블록을 비교한다는 것이다.

### 측정 / 판정 (`src/jenga_vision/seam.py`)
- 사진마다 프로그램이 이음매(아래쪽 끝면들 사이의 가장 어두운 세로줄)를 찾는다. 그 왼쪽과 오른쪽에서 각각 새까만 틈 두께(px)를 잰다. `step = 왼쪽 틈 - 오른쪽 틈`.
- 이음매 2개 × 양쪽 끝 = 층당 4장을 찍는다. 블록 높이는 가운데 대비로 계산해서 양쪽 끝 평균을 낸다.
- 제일 높은 블록보다 `--tol`(기본 2px) 이상 낮은 블록을 easy로 예측한다.
- 결과 파일: `seams.csv`(사진별 틈), `blocks.csv`(블록별 높이, 예측, 실제).

### 미니 탑 첫 사진 (참고)
- 1층, 1번 면: 왼쪽 이음매 15.5 / 15.5, 오른쪽 이음매 20.5 / 19.0 → 이쪽 끝에서는 세 블록 높이가 거의 같았다.

   - 이음매를 하늘색 세로선에, 위층과의 경계를 양옆 하늘색 표시에 맞춘다.
   - 초록 세로선(프로그램이 찾은 이음매)이 하늘색 선과 겹치는지 확인하고 SPACE를 누른다.
5. **밀어보기 (45개, 한 번만):** `jenga-seam`의 확인 단계에서 화면 순서대로(층마다 왼쪽, 가운데, 오른쪽) 밀고 `e`/`h`를 누른다.
   - 빼지 말고 살짝 밀어보고 원래 자리에 되돌린다. 애매하면 `h`.
   - 가운데도 **건너뛰지 말고 전부** 민다.
6. 분석 (Claude):
   - 이음매 방식의 블록별 정답률, 특히 가운데 블록
   - 같은 정답으로 사이드 방식 채점 → **블라인드 연속 성공 개수**
   - 두 방식을 합치면 나아지는지

### 판단 기준
- 이음매 방식이 가운데 블록을 꽤 맞히면(예: 15개 중 12개 이상) → 사이드 + 가운데 통합 판정 도구로 만든다.

```bash
cd ~/CES2027/JENGA_VISION_DINO
```
