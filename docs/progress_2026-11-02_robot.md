## 남은 문제
- **얇은 틈을 놓친다.** 0 px 15개 중 L05 가운데, L11 오른쪽, L13 오른쪽, L15 오른쪽은 가는 검은 선이 폭의 70~80 %에 보인다. `measure_end`가 띠 폭의 25 백분위를 써서, 선이 끊기거나 얇으면 0이 된다. 그래서 상위권은 잡히지만 **중간 순위는 0점 동점**이다. 후보: 띠 안의 어두움을 면적으로 재기, 어두운 열의 비율 함께 쓰기. 예전 탑의 실제 결과로 검증할 것.
- **아랫 모서리 실제 사진 없음**: `edge_side` 판정은 가상으로만 확인. 윗 모서리는 실제 사진 전부 맞음.
- **Dino가 숙여지는 기울기(축 둘레 회전이 아닌 것)**는 보정하지 않는다. 화면 한쪽만 계속 흐리면 그때 대응.
- 기울기 영향: 소프트웨어 회전 시험에서 8°까지 틈 변화 1 px 이내, **10°에서 측정 실패**. 자동 보정 한계도 10°.
- 동료에게 확인: 탑 높이 z 0.051(동료 `tower_pose.yaml`, 10/30 기록) vs 0.101(우리). 층 높이 22.36 vs 21.86 mm. 최신 URDF, 메시는 받은 `jenga_miller_sw`에 없음(별도 저장소 `jenga_bringup`, `hardware`).

## 코드 현황
- **`focus_search.py`** `find_peak`: 바깥 먼저 → 더 좋은 곳이 없으면 도착점으로 돌아와 안쪽 → 양쪽이 12 % 넘게 2번 연속 떨어지면 최고점, 주변 값으로 곡선 맞춤. 간격 1 mm. 바닥값 위 봉우리만 인정(`min_focus` 12).
- **`autoscan.py`**
  - 첫 블록, 옆 블록, 재초점이 모두 `find_peak`. 안쪽 한계 `--max-in-mm` 8, `--limit-mm` 6, `--prior-depth-mm -5`, `--prior-down-mm -3.9`.
  - `SETTLE_S` 1초, 초점 측정 3장 중간값.
  - 라인 찾기는 어두운 틈 대신 끝면의 **밝은 테두리**(`edge_row`, `rim_rows`). 틈이 닫힌 블록도 찾는다. 실제 사진 15장 모두 찾음, 라인 없는 사진 61장 오검출 0.
  - 재초점은 1 mm 넘게 움직였거나 회전했을 때만.
  - **직선 이동 가감속 `ramped`**(200 mm/s²): 빠른 이동용. **기준 스캔 이후에 넣어서 실기 미확인.**
  - `rank`가 동료 형식 `jenga_pick_candidates.json`도 씀(`--candidates 경로`, 동료 기본 경로는 `$JENGA_STATE_DIR/jenga_pick_candidates.json`). score는 `jenga-ends` 상대 점수라 음수도 있음. 스캔 층 3~15(`scan_layers`): 동료 규칙상 3층 아래와 맨 위 16층은 안 뽑는다.
- **`focus_probe.py`** `jenga-focus hold|curve|sweep`. `curve`, `hold`는 현재 자세에서 바깥으로만 움직이고, `sweep`은 세션 값으로 층을 훑어 프레임별 틈을 잰다. 결과 `captures/focus_*`, `captures/sweep_*`.
- `jenga-view`의 focus 숫자를 `autoscan`과 같은 지표로 바꿈(`camera.focus_value`).
- `arm_poses.json` (right): `focus_far_l13`, `1102_s13_best_focus`, `1102_s13_line`. `tip_to_focus_m` 0.025.
- 시험: `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 uv run --with pytest pytest tests/` (69개, 실측 곡선 재생, 기록 안 된 안쪽은 바깥쪽을 대칭으로 씀). 가상: `--send` 없이, 또는 domain 77에서 `jenga-sim --no-rviz --time-scale 20` + `--send --fake`.
