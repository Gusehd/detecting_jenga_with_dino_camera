젠가 스캔 v2: 집기부터 꽂기까지 약 3분 15초, 연속 15~20개 정답

오른팔 xArm7에 쥔 Dino-Lite 카메라로 젠가 탑 두 면(−y, +x)의 블록 끝 틈을 찍고, 뽑을 순서를 정하는 과정을 빠르게 만든 결과입니다. 11-03 실기에서는 두 면 스캔에만 약 16분이 걸렸습니다. 오늘 집기·스캔·꽂기 전체를 3분대로 줄였고, 정확도는 떨어지지 않았습니다.

결론

  • 속도 목표: 전체 3분 30초를 목표로 잡았고, v2가 보통 3분 15~20초로 들어왔습니다. 조건이 나쁘면 4분 안쪽, 좋으면 3분 05초까지 나옵니다.
  • 정확도: 연속 8개가 목표였습니다. 탑 두 개에서 15개와 20개를 맞혔습니다. 같은 탑을 느린 방법(v1)과 빠른 방법(v2)으로 찍었을 때 점수가 같아, 속도를 올려 정확도를 잃은 흔적은 없습니다.
  • 2분대는 두 면으로는 어렵습니다. 남은 시간 대부분이 기준점 잡기(초점·라인)와 멈춰서 찍기처럼 꼭 필요한 동작입니다. −y 한 면만 쓰면 약 2분 10~20초가 되지만, 탑에 따라 연속 정답이 7~12로 흔들렸습니다.
  • 남은 검증: 지금까지 정답은 손으로 살살 밀어서 확인했습니다. 로봇이 순서대로 실제로 뽑는 연속 시험은 아직 하지 않았습니다.

인수인계 가이드

처음 맡는 사람이 이 순서대로 하면 됩니다. 자세한 기록은 저장소의 docs/progress_2026-11-02_robot.md 맨 위 "지금 기준 실행 가이드"에 있습니다.

1. 준비 (매번)

  1. 로봇 PC: 컨테이너 jenga-ros2에서 제어 스택을 띄웁니다. 시작 전에 양쪽 xArm의 비상정지(C2)가 풀려 있는지 확인합니다.
  2. 비전 PC 터미널: 로봇을 다루는 터미널은 항상 이렇게 시작합니다. 
    cd ~/CES2027/JENGA_VISION_DINO
source tools/robot_env.sh          # ROS 도메인 42, USB LAN 설정, ros2 daemon 재시작
ros2 topic hz /joint_states        # 약 30 Hz가 나오면 Ctrl+C
  3. 처음 한 번만: 소켓 버퍼 확장 sudo sysctl -w net.core.rmem_max=4194304 net.core.wmem_max=4194304 (재부팅 후 유지는 /etc/sysctl.d/60-dds.conf)
  4. 현장: 다이얼 40, 팔은 home, Dino는 지그에 똑바로 꽂고 손은 비움. jenga-view, jenga-arm, jenga-hand 창은 닫음.
  5. 탑 방향: −y 면에서 볼 때 1층에 블록 끝면(작은 면) 3개가 보이게 쌓습니다. +x 면에서는 1층에 긴 옆면, 2층에 끝면 3개가 보입니다.

# 멈추기: 터미널에서 Ctrl+C (팔은 그 자리에 섬)

4. 문제가 생기면

증상원인조치
no /joint_states로 바로 끝남로봇 스택이 꺼짐, 또는 robot_env.sh를 안 한 터미널스택 확인 후 source tools/robot_env.sh, ros2 topic hz /joint_states
sequence size exceeds remaining buffer가 계속 뜸로봇 PC(Jazzy)와 비전 PC(Humble)의 버전 차이무해함. 무시
블록마다 10초 넘게 위아래로 오가며 느림라인을 못 찾음: 탑을 반대 방향으로 쌓음, 또는 Dino가 손안에서 20° 넘게 돌아감Ctrl+C → 탑 방향 확인, Dino를 꽂았다 다시 집기
STOPPED: no reference로 탑 앞에서 멈춤기준점에서 라인을 못 찾음 (대개 탑 방향 문제)탑 바로 옆에서 관절 이동 금지. uv run jenga-arm --arm right --send --speed 10 → Sync → 탑에서 멀어지는 방향(+x 면이면 base +x, −y 면이면 base −y)으로 5 mm씩 약 50 mm jog → cali_way_1 → home → place_dino_quick
집을 때 Dino가 덜렁거리거나 틀어짐지그 위치나 집는 자세가 어긋남jenga-arm에서 final_grasp_1_1109_xp5를 다시 맞추고 같은 이름으로 저장 (config/arm_poses.json, 저장 전에 백업)

5. 핵심 파일과 안전

  • src/jenga_vision/autoscan.py: 스캔 전체. 설정 묶음은 PRESETS(v1, v2), 속도는 QUICK·FAST
  • config/tasks.json: 집기·꽂기 순서와 속도. config/arm_poses.json: 팔 자세. config/scan_setup.json: 탑 위치와 Dino 보정값
  • captures/.last_start.json: 지난 스캔의 첫 블록 깊이·높이 (다음 스캔의 시작점, 8 mm 넘게 다르면 자동으로 무시)
  • 시뮬레이션: 도메인 77에서 uv run jenga-sim + 같은 명령에 --fake. 실제 로봇은 도메인 42(예전 0)라 jenga-sim은 거기서 실행을 거부함
  • 로봇을 움직이는 명령은 사람이 현장을 보면서 직접 실행합니다.

한계와 다음 단계

  • 한쪽 끝만 보는 한계: 블록의 −y 또는 +x 쪽 끝만 찍습니다. 반대쪽 끝(+y, −x)은 오른팔이 닿지 않습니다. 새 탑의 4층(왼쪽 틈 10.8, 가운데·오른쪽 0)과 5층(10.0, 0, 0)은 값이 거의 같은데 처음 밀어 본 정답이 달랐습니다. 이런 층은 순서 규칙만으로는 구분할 수 없습니다. 근본 해결은 왼팔로 반대쪽 면도 찍는 것인데, 시간이 거의 두 배가 됩니다.
  • 실제 연속 뽑기 시험: 로봇이 출력된 순서대로 하나씩 뽑을 때 몇 개까지 가는지 확인이 필요합니다. 블록을 빼면 위층 하중이 바뀌므로 밀어 보기보다 낮게 나올 수 있습니다.
  • 최악 시간 줄이기 (선택): 블록마다 라인을 다시 찾는 범위를 ±12 mm에서 ±5 mm로 줄이면, 고장 상황의 최악 시간이 7~8분에서 약 4분 30초로 줄어듭니다. 보통 시간에는 영향이 없습니다.
